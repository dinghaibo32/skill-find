# API 冒烟测试

## 概述

用最小请求集合快速验证 API 是否"活着且基本正确"：状态码、响应结构、关键业务字段。核心原则：只读优先，冒烟请求不得产生脏数据；写接口用可回滚的测试数据。

## 使用步骤

1. **确认目标**：向用户确认 base URL、待测端点清单、鉴权方式（无/API Key/Bearer）。端点不明时先读项目的路由定义或 OpenAPI 文档。
2. **准备请求**：需要构造请求体时，读取附带模板 `templates/request-template.json`，按端点替换字段。仅在构造写接口请求时读取。Windows PowerShell 下发送 JSON 一律先写入临时文件再用 `curl.exe -d @文件`，避免内联 JSON 转义失败。
3. **按序执行**：
   - 健康检查端点（如 `/health`）→ 期望 200；
   - 核心读接口 → 期望 200 且响应含关键字段；
   - 鉴权负例：不带 token 访问受保护端点 → 期望 401/403；
   - 写接口（如有）→ 用带 `smoke-test` 标记的数据创建，随后删除或记录待清理。
4. **判定与报告**：每个端点输出「端点 | 期望 | 实际状态码 | 结构校验 | 结论」。任一失败立即标注，全部完成后给出通过率汇总。
5. **失败处理**：区分连接失败（服务未起/端口错）、4xx（请求或鉴权问题）、5xx（服务端缺陷），分别给出下一步建议；服务端缺陷转交调试流程，不在本 skill 内改代码。

## 常见错误

| 错误 | 修正 |
|------|------|
| 冒烟时批量创建真实业务数据 | 只用带标记的测试数据并清理 |
| 只看状态码不看响应结构 | 校验关键字段存在且类型正确 |
| PowerShell 内联 JSON 转义炸掉 | `-d @file` 方式发送 |
